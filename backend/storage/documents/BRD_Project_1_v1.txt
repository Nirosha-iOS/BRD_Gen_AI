## 1. Project Overview

**Project Name:** Sales360 Application
**Objective:** Develop a mobile and web application to manage sales leads, commitments, meetings, and follow-ups for BM and BDO users.
**Project Type:** Software Application
**Target Users:** BM, BDO, and other stakeholders involved in the sales process.
**Business Value:** Improve sales performance, enhance collaboration, and provide real-time insights into the sales pipeline.

---

## 2. Stakeholders

| Role | Responsibility |
|------|----------------|
| BM (Business Manager) | Creates lead and commitments, reviews progress |
| BDO (Business Development Officer) | Creates lead and commitments, follows up with prospects |
| Sales Team | Uses the application for daily activities |

## 4. Application Scope

### 4.1 Mobile Application

The mobile application will allow BM and BDO users to:

* Create new leads
* Edit existing commitments
* View upcoming meetings
* Follow up with prospects

#### Core Features

1. **Lead Creation**: Users can create new leads, including mandatory and additional commitment details.
2. **Commitment Editing**: Users can edit existing commitments, updating status and completion dates.
3. **Meeting Scheduling**: Users can schedule meetings and appointments.

### 4.2 Web Application (Admin)

The web application will provide an administrative interface for:

* Lead management
* Commitment tracking
* Meeting scheduling
* User management

#### Key Capabilities

* View lead pipeline and commitment status
* Edit user roles and permissions
* Generate reports on sales performance

---

## 5. Business Requirements

### BR-001: Lead Creation

**Priority:** High  
**Description:** Allow BM and BDO users to create new leads, including mandatory and additional commitment details.

**Business Rules:**

* Leads must have a unique identifier
* Mandatory commitments are required for each lead
* Additional commitments can be added as needed

**Acceptance Criteria:**
- ✅ Lead creation is successful when all mandatory commitment fields are filled.
- ✅ Users can add multiple additional commitments per lead.
- ✅ The application validates input data and prevents invalid entries.

---

### BR-002: Commitment Editing

**Priority:** Medium  
**Description:** Allow BM and BDO users to edit existing commitments, updating status and completion dates.

**Business Rules:**

* Commitments must have a unique identifier
* Status updates require approval from the lead owner (BM or BDO)
* Completion dates can be updated by the commitment owner

**Acceptance Criteria:**
- ✅ Commitment editing is successful when all required fields are filled.
- ✅ The application validates input data and prevents invalid entries.
- ✅ Approval processes for status updates are implemented.

## 7. Technical Overview

### 7.1 System Architecture

```
Mobile Application 
|--- Frontend (Flutter) ---|
|                             |
|    Backend (Java Spring)   |
|                             |
|--- Database (AWS RDS) ---|
```

### 7.2 Technology Stack

#### Frontend (Flutter)

* Layer 1: UI Components
	+ Flutter widgets for creating leads, editing commitments, and viewing meetings
* Layer 2: Business Logic
	+ Implement business rules and validation logic using Dart language
* Layer 3: Data Storage
	+ Store data locally using SQLite or other suitable storage solution

#### Backend (Java Spring)

* Layer 1: RESTful API
	+ Expose RESTful API endpoints for lead creation, commitment editing, and meeting scheduling
* Layer 2: Business Logic
	+ Implement business rules and validation logic using Java language
* Layer 3: Data Storage
	+ Store data in AWS RDS database

#### Infrastructure/Cloud (AWS)

* Service | Usage |
|---------|-------|
| EC2     | Hosting the application instances |
| S3      | Storing static assets and files |
| RDS     | Storing relational data |
